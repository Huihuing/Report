# Fridge Chef — 프로젝트 계획서 v1

- 작성자: limheejae
- 작성일: 2026-10-10
- 과제: ALEPH 프리미엄 · 바이브코딩
- 상태: v1 (이후 수정 시 v2 파일을 별도로 기록)
- 범위: 주말 내 공개 가능한 정적 웹 MVP

## 1. 한 줄 소개
냉장고에 남은 식재료를 입력하면 만들 수 있는 요리를 추천하고 부족한 재료까지 알려주는 웹앱.

## 2. 대상 사용자
자취생, 요리 초보자, 남은 재료를 활용하고 싶은 일반 사용자.

## 3. 핵심 기능 — 정확히 3개
1. **식재료 관리:** 식재료 추가·삭제, 중복 방지, 브라우저 로컬 저장.
2. **레시피 추천:** 검토 가능한 내장 예시 레시피 20개 이상과 보유 재료를 비교하여 적합도순 추천.
3. **부족한 재료 안내:** 요리별 보유 재료와 부족한 재료를 구분하고 바로 만들기 후보를 표시.

## 4. 명확한 완료 기준
- 20개 이상의 고유 레시피가 로딩된다.
- 사용자가 재료를 추가·삭제하고 새로고침 후에도 목록이 유지된다.
- 같은 재료를 중복 입력하거나 빈 문자열·과도하게 긴 값을 입력하면 안내한다.
- 레시피별 필요한 재료 집합과 보유 재료의 교집합·차집합이 정확하다.
- 후보가 보유 재료 일치도(동률인 경우 부족 개수 등) 순서로 정렬된다.
- 0개·1개·여러 개 입력, 별명(달걀/계란), 없는 조합, 스토리지 실패 등에 대응한다.
- PC·모바일에서 사용 가능하며, 별도 로그인 없이 공개 URL로 접속한다.
- 등록한 재료는 이 브라우저의 localStorage에만 보관하며 서버로 전송하지 않는다.

## 5. 기술 선택과 이유
- HTML/CSS/바닐라 JS: 빌드 과정 없이 로컬 파일에서 테스트 가능.
- JSON 성격의 정적 JS 레시피 목록: 별도 DB·API 호출이 없고 데모 재현이 쉽다.
- localStorage: 로그인/서버 없이 사용자 입력을 보관한다.
- GitHub feat/fridge-chef: 기존 과제와 격리하며 Vercel Preview를 비활성화한다.
- 최종 검증 후 main 병합 및 단일 Vercel 프로덕션 배포. 사용자가 승인하기 전에는 배포하지 않는다.

## 6. 점검과 기록
### 중간 점검 1 — 기반
- 이번에 만든 것: 기본 화면, 재료 입력·삭제, 중복 처리, 영속 저장.
- 3단계 확인: (1) 페이지 열기 (2) '계란' 추가 후 다시 입력 (3) 새로고침/삭제 확인.
- 판단 기록: 로그인·백엔드 대신 브라우저 저장 선택.
- 제한: 결과 URL 필수 여부를 Workbench에서 확인. 공개 Vercel 배포는 최종으로 미룬다.

### 중간 점검 2 — 추천
- 이번에 만든 것: 레시피 매칭, 추천 정렬, 부족 재료 표시.
- 3단계 확인: (1) 계란·밥 추가 (2) 추천 결과 확인 (3) 재료 추가 후 부족 재료 변화 확인.
- 판단 기록: 생성 AI의 임의 조리법이 아니라 검증 가능한 고정 데이터와 결정적 규칙.

### 최종 제출 — 품질
- 반응형 디자인·빈 상태·이상 입력 점검.
- 자동 테스트 + 브라우저 수동 점검. 확인하지 않은 시험·승인·사용후기는 통과로 기록하지 않는다.
- 마지막에만 main 병합→공개 Vercel 배포→익명 브라우저 HTTP 200 확인.
- 보고서에는 결과 URL, 소스의 **40자리 전체 커밋 SHA URL**, 확인 절차 4가지, AI/본인 판단 3줄을 기재.

## 7. 범위에서 제외한 내용
AI 레시피 생성, 외부 레시피 API, 영양·알레르기 안전 판단, 재고 수량·소비기한 관리, 계정·동기화, 영상·사진 인식은 제외.
레시피는 간소화된 예시이며 조리의 안전성과 실제 가능성을 보증하지 않는다.
