## 중간 점검 1 (작성 초안)

**이번에 만든 것**  
재료 직접 입력, 12개 빠른 추가 버튼, 중복 입력 검사, 재료 삭제/모두 삭제, \`localStorage\` 보존.

**3단계 확인**
1. \`fridge-chef/index.html\`을 로컬 브라우저로 열기.
2. '계란'을 추가한 뒤 다시 '달걀'을 추가하여 중복 거절을 확인.
3. 새로고침한 뒤 보존 여부를 확인하고 재료 하나 삭제.

**바뀐 점과 이유**  
로그인·서버 DB 대신 브라우저 로컬 저장을 선택해 주말 내 구현 범위와 개인정보 노출 위험을 줄였다.

**AI와 본인 판단**  
- AI에 맡긴 일: 화면 구성과 입력 검증·저장 코드 구현 및 테스트 보조.
- 본인이 판단한 일: 핵심 기능 3개와 레시피 정적 데이터, Vercel 마지막 배포 제한.
- 다음에 할 일: 실제 추천 결과 및 부족 재료 검사.

## 중간 점검 2 (작성 초안)

**이번에 만든 것**  
32개 예시 레시피, 별칭 정규화, 정확한 재료 교집합/차집합 계산, 일치도 순 정렬, 기본 재료 충족 필터, 요리명 검색.

**3단계 확인**
1. 냉장고에 '밥', '계란'을 추가한다.
2. '간장계란밥'의 일치도가 100%이고 필요한 기본 재료가 모두 있다는 표시를 확인한다.
3. '계란'을 삭제하여 부족한 재료가 '달걀'로 바뀌는지 확인한다.

**바뀐 점과 이유**  
생성형 AI의 즉흥 추천보다 결과를 재현할 수 있는 고정 레시피 자료와 결정적인 일치도 정렬을 선택했다.

**AI와 본인 판단**
- AI에 맡긴 일: 추천 로직·카드 UI·재료 비교 알고리즘.
- 본인이 판단한 일: 실제 조리 가능·식품 안전 보증으로 오해할 수 없도록 제한 문구 삽입.
- 다음에 할 일: 반응형·빈 상태·저장 실패·최종 브라우저 검사, 최종 배포.

## 4가지 재현·통과 확인 초안

1. \`/fridge-chef/\` 접속 또는 \`fridge-chef/index.html\` 로컬 실행.
2. '밥', '계란' 입력 후 추천의 '간장계란밥'을 확인.
3. 매칭 100%, 누락 0개인지 확인하고 '계란' 삭제 후 누락 '달걀' 1개 확인.
4. 새로고침 후 나머지 재료가 보존되고 잘못된 입력은 오류 안내만 출력되는지 확인.

주의: 공개 URL은 배포가 실제 완료된 다음 기재한다. 중간 점검 1이 결과물 URL을 반드시 요구한다면 로컬 URL을 공개 URL처럼 제출하지 말고, 담당자에게 인정되는 증거 형식을 확인하거나 점검 시점에 맞춰 배포 계획을 조정한다.
