# T02 제출 준비

## 결과물

- 결과물 URL: https://report-huihuing.vercel.app/t02/
- 소스 URL: 제출 직전 최신 40자리 full commit URL을 사용한다.

## 재현·통과 확인 4가지

1. **어디로 가나요:** 공개 결과물 URL의 Gate Sprint 30 첫 화면으로 이동합니다.
2. **3단계 이내 무엇을 하나요:** 게임 시작 → 목표 색과 같은 좌우 문을 선택하고 필요하면 P로 일시정지/재개 → 성공 또는 실패 뒤 다시 시작합니다.
3. **무엇이 보이면 통과인가요:** 입력 한 번이 한 번만 처리되고 30초 안에 성공/실패가 결정되며, 일시정지·포커스 복귀·다시 시작 후 상태가 올바르게 이어지거나 초기화됩니다.
4. **안 될 때 무엇이 보이나요:** 한 입력이 중복 처리되거나 이탈/일시정지 중 시간이 흐르고, 재시작 뒤 이전 판 진행도가 남거나 게임을 계속 조작할 수 없으면 실패입니다.

## AI와 내 판단 3줄

1. **AI에게 맡긴 일:** 게임 상태·타이머·좌우 입력, 일시정지/포커스 복구, 저장 손상 복구, 20회 난이도 기록, 성공 효과와 효과 줄이기 기능 구현 및 기준 점검을 맡겼습니다.
2. **직접 판단한 일:** 좌우 문 통과 게임으로 정하고 목표 색과 같은 문을 고르는 규칙, 30초 제한, 난이도 비교값을 관문 수 8개와 10개 하나만 바꾸는 방식으로 결정했습니다.
3. **AI 제안을 따르지 않은 일:** 리듬 게임은 음악 자료와 판정 구현이 추가로 필요해 사용하지 않았고, 과제별 별도 Vercel 프로젝트도 만들지 않고 기존 report 프로젝트의 /t02/ 경로를 사용했습니다.

## 카드별 대응

- T02-C01: 기존 report Vercel 공개 경로와 공개 GitHub full commit URL 사용.
- T02-C03~C09: 공개 규칙/조작/상태, 30초 종료, 성공·실패 뒤 재시작 초기화.
- T02-C10~C17: 반응형 UI, 동일 keydown 10건 자체검사, resize 상태 유지, 포커스 자동 정지/복귀, 수동 일시정지. 두 해상도 및 10분 실행은 실제 브라우저 최종 확인 필요.
- T02-C18~C21: 변경 전 8문 10회/변경 후 10문 10회 자동 기록 장치와 통계/최종 선택 이유 생성. 실제 20회 플레이 필요.
- T02-C22~C25: 현재 판 값과 보존 기록 분리, localStorage 정상/빈 값/문법 손상/구조 손상 기본값 복구.
- T02-C26~C27: 최종 성공에서만 success pulse 실행, 효과 줄이기 버튼으로 즉시 중지.
- T02-C28~C29: 개인정보/비밀값 원문을 공개 화면과 새 변경 파일에 넣지 않음.
- T02-C30~C31: 이 문서의 4줄/3줄로 구분.

## 제출 직전 실제 확인

- [ ] 1366×768: 조작 영역 잘림 0, 가로 넘침 0.
- [ ] 1920×1080: 조작 영역 잘림 0, 가로 넘침 0.
- [ ] "1초 내 동일 입력 10건 자체검사" PASS.
- [ ] 창 크기 변경 뒤 상태/조작 유지.
- [ ] 포커스 이탈/복귀 뒤 같은 판 유지.
- [ ] 일시정지 중 진행 없음, 재개 뒤 이어짐.
- [ ] 10분 연속 실행 뒤 조작 가능.
- [ ] 10분 연속 실행 뒤 DevTools Console 빨간 오류 0건.
- [ ] 변경 전 8문 10회 실제 플레이.
- [ ] 변경 후 10문 10회 실제 플레이.
- [ ] 20회 기록을 보고 최종 8문 또는 10문 선택 저장.
