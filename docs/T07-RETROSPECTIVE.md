## 증거의 종류 (수정 불가한 사실 구분)

이것은 GitHub의 **서로 다른 다섯 KST 날짜에 존재했던 공개 Git commit 기록을 2026-10-08에 재구성한 회고**이다.

- 실제로 확인 가능한 사실: 특정 공개 Git 저장소에 해당 commit SHA와 committer timestamp의 기록이 존재한다.
- 재구성한 항목: 어떤 다섯 날짜/저장소를 모을지와 비교 구간의 선정, 일별 커밋 수의 집계.
- 주장하지 않는 것: 해당 날짜에 T07 인증 앱에 로그인해 사용했다는 사실, 실제 5일 연속 사용, 커밋 수가 개인 집중시간이라는 주장, 당시 2일차와 3일차 사이에 계획 규칙을 바꿨다는 주장.
- 따라서 본 자료는 T07의 **활동 근거·회고/계산 검산 보조 증거**이고, 로그인 후 5일간 실제 사용이라는 항목(T07-C07 및 C09~C12)의 정식 대체 증거가 아니다.
- **개인 채팅 원문이나 다른 비공개 저장소 기록은 공개하지 않았다.** 채팅 요약이나 기억만으로 만들기보다 공개 SHA를 1차 자료로 택했다.

## 질문 / 지표 / 단위 / 계산 규칙

**회고 질문:** 선택된 과거 5개 실제 개발 활동 날짜에, 공개 저장소의 확인 가능한 커밋이 몇 건 있었는가?

- **지표:** 선택한 공개 Git 저장소 세 곳의 날짜별 유일한 commit SHA 개수.
- **단위:** 건/일 (commits per selected day).
- **날짜 규칙:** `commit.committer.date`(UTC)를 Asia/Seoul(+09:00)로 변환하여 `YYYY-MM-DD` 추출.
- **중복:** `(repository_full_name,SHA)` 조합을 하나로 계산.
- **결측:** 근거가 없는 날짜를 임의의 0으로 채우지 않는다. 이 자료는 선정된 다섯 날짜만 분석하며 나머지는 분석 대상 밖.
- **이상치:** 커밋 수가 큰 날도 제거하지 않는다. 자동화·일괄 커밋·리포지토리 차이로 극단값이 나타날 수 있음을 표시한다.
- **반올림:** 합계는 정수; 평균은 소수 첫째 자리.
- **주 시작일:** 월요일, 단 이 5개 선택 날짜는 연속 주간 통계가 아니다.

### 손계산

```text
일별 수     = [67, 3, 3, 61, 96] 건
전체 합계   = 67 + 3 + 3 + 61 + 96 = 230 건
5일 평균    = 230 / 5 = 46.0 건/선택일
처음 2일    = (67 + 3) / 2 = 35.0 건/선택일
나중 3일    = (3 + 61 + 96) / 3 = 53.3 건/선택일
단순 평균차 = 53.3 - 35.0 = +18.3 건/선택일
```

마지막 차이는 **관찰치 비교**일 뿐, 계획 규칙 변경의 효과가 아니다. 그 사이에 실제로 규칙을 변경했다는 동시대 증거가 없으므로 **T07-C09~C12 충족이라고 주장하지 않는다**.

### 실행

```sh
node t07/evidence/verify.mjs
```

이 스크립트는 JSON의 SHA 40글자 형식, 공개 저장소 이름, 다섯 날짜, 중복, 커밋 시각→KST 날짜, 고정 일별 집계와 합계를 직접 계산한다.

공개 GitHub의 개별 SHA를 원본 출처 링크로 제공한다. Git 커미터 날짜는 저장소 관리자가 지정할 수 있어, SHA 링크는 기록의 추적 가능성을 제공하지만 해당 일에 사람이 몇 시간을 작업했는지는 증명하지 않는다.

## 실제 T07 앱 사용은 별도 기록으로 유지

T07 앱 자체의 5일 실사용 데이터는 각 날짜에 **실제로 로그인해 기록**해야 한다. 지금 회고 JSON을 `t07_day_entries`에 '그날 이미 사용했다'는 형태로 소급 삽입하지 않았다. 이 구분 때문에 C07/C09가 미충족이라도 회고 결과의 증거 신뢰성은 유지된다.

**AI와 내 판단:** 자동 수집·계산·표시는 AI에게 맡김. 공개 SHA만 근거로 사용하고 비공개 대화는 노출하지 않기로 판단함. 과거 대화를 마치 당시 앱 기록이나 당시 변경한 규칙처럼 만드는 접근은 채택하지 않음.
