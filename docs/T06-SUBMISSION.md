## 재현·통과 확인 4가지

1. **어디로 가나요:** 공개 T06 플랜두씨 다이어리의 Plan → Tasks → Do → See 화면으로 이동합니다.
2. **세 단계 안에 무엇을 하나요:** 계획과 수정 이력 확인 → 할 일 완료/검색 또는 실행 기록 확인 → See 집계 숫자를 눌러 근거 기록으로 이동합니다.
3. **무엇이 보이면 통과인가요:** 실제 ALEPH 계획·할 일 5개 이상·실행 기록 3개 이상이 서버 DB에서 보이고, 새로고침 후 유지되며 집계 숫자를 누르면 근거 기록으로 이동하고 돌아보기 한 줄이 다음 계획에 저장됩니다.
4. **안 될 때는 무엇이 보이나요:** 새로고침 후 값이 사라지거나 계획 수정 전 값이 없어지고, 완료 요청이 중복 기록되거나 집계 숫자와 근거 기록 수가 맞지 않으면 실패입니다.

## AI와 내 판단 3줄

1. **AI에게 맡긴 일:** PostgreSQL 스키마와 Edge Function, Plan/Task/Do CRUD, 수정 이력·중복 완료 방지·집계·JSON 내보내기·공개/비밀값 검사를 구현하고 점검하도록 맡겼습니다.
2. **내가 직접 판단한 일:** 공개 화면에 개인적인 일기 대신 현재 실제로 진행 중인 ALEPH T06 계획과 작업 기록만 넣고, 로그인 없는 T06에서는 남이 봐도 괜찮은 내용만 사용하기로 결정했습니다.
3. **AI 제안을 따르지 않은 일:** 브라우저에 DB key를 두고 직접 Supabase 테이블을 조작하는 단순한 구조는 사용하지 않고, 비밀값을 서버 Edge Function에만 두는 구조로 분리했습니다.
