## 실제로 넣은 내용

오늘 실제 계획:

> 아침 일찍 과제 4 완료를 시작으로 마지막 과제 13까지 최대한 진행한다.

현재 실제 상태:

- 과제 4 완료
- 과제 5 완료
- 과제 6 진행 중
- 과제 7~13 예정

Do는 오늘 Git commit으로 확인되는 실제 구간 3건을 저장했다.  
See에는 과제 5에서 여러 AI 검증/재검증 때문에 예상보다 오래 걸렸다는 점과, 다음 과제부터 검증 기준을 먼저 고정해 반복을 줄이겠다는 결론을 저장했다.

## 재현·통과 확인 4가지

1. **어디로 가나요:** 공개 T06 플랜두씨 다이어리의 Plan → Tasks → Do → See 화면으로 이동합니다.
2. **세 단계 안에 무엇을 하나요:** 오늘 과제 4~13 계획과 수정 이력 확인 → 실제 Do 기록 확인 → See 집계 숫자를 눌러 근거 기록으로 이동합니다.
3. **무엇이 보이면 통과인가요:** 실제 오늘 계획, 과제 4~13의 할 일 10개, Git 근거 Do 3건, 과제 5 검증 지연에 대한 See가 서버 DB에서 보이고 새로고침 뒤 유지되며 돌아보기 한 줄이 다음 계획으로 이어집니다.
4. **안 될 때는 무엇이 보이나요:** 새로고침 후 값이 사라지거나 수정 전 계획이 없어지고, 완료 요청이 중복 기록되거나 집계 숫자와 근거 기록 수가 맞지 않으면 실패입니다.

## AI와 내 판단 3줄

1. **AI에게 맡긴 일:** PostgreSQL/Edge Function/CRUD/집계/내보내기 구현, Git 커밋 근거 정리, 서버 DB 중복 완료 검사와 공개·비밀값 검증을 맡겼습니다.
2. **내가 직접 판단한 일:** 오늘 실제 목표를 “과제 4 완료를 시작으로 과제 13까지 최대한 진행”으로 정했고, 과제 5의 여러 AI 검증이 오래 걸렸다는 점을 실제 See로 남기기로 했습니다.
3. **AI 제안을 따르지 않은 일:** 초기 AI 검증용 임시 계획/실행시간을 내 실제 기록처럼 사용하지 않고 제거했으며, 실제 계획과 Git에서 확인되는 Do 구간으로 교체했습니다.
