# T01 제출 준비

> 실제 제출 직전에 URL과 테스트 결과를 다시 확인하고 이 문서를 최종 갱신합니다.

## 결과물

- 결과물 주소: 공개 배포 후 입력
- 소스 주소: 저장소 공개 전환 후 `https://github.com/Huihuing/Report/commit/<40자리-full-commit-sha>` 형식으로 입력

## 짧은 확인 방법 4줄

1. **위치:** 공개 결과물 주소의 첫 화면에서 시작합니다.
2. **3단계 이내 행동:** 프로젝트 영역으로 이동 → ‘복원’ 필터를 선택 → 표시되는 프로젝트 카드와 공개 범위 안내를 확인합니다.
3. **통과 모습:** 복원 관련 카드만 남고, 저장소 대신 공개 가능한 설명과 스크린샷 영역이 정상적으로 표시됩니다.
4. **안 될 때 모습:** 필터를 눌러도 카드가 바뀌지 않거나 프로젝트 영역이 겹치거나 잘려 내용을 확인할 수 없습니다.

## AI와 나의 판단 3줄

1. **AI에게 맡긴 일:** 페이지의 기본 구조, 반응형 CSS, 키보드 접근이 가능한 버튼 동작과 제출용 점검 문서 초안을 작성하게 했습니다.
2. **직접 판단한 일:** 누구에게 무엇을 보여줄지, 어떤 개인정보와 프로젝트 자료를 공개하지 않을지, 저장소 대신 스크린샷으로 보여줄 작업을 결정했습니다.
3. **AI 제안을 따르지 않은 일:** 모든 프로젝트의 GitHub 저장소를 직접 연결하는 초기안은 제3자 저작물이나 원본 자료가 포함될 가능성을 고려해 사용하지 않고, 공개 권한이 명확한 경우에만 Repository 링크를 제공하기로 했습니다.

## 화면·상호작용 검사

### 기준 화면 A — 모바일
- 권장 확인 크기: 390 × 844
- [ ] 가로 스크롤 없음
- [ ] 제목과 버튼이 겹치지 않음
- [ ] 프로젝트 카드와 스크린샷이 한 열로 표시됨
- [ ] 모든 링크와 버튼을 누를 수 있음

### 기준 화면 B — 데스크톱
- 권장 확인 크기: 1440 × 900
- [ ] 본문 폭과 여백이 자연스러움
- [ ] 카드와 스크린샷이 겹치거나 잘리지 않음
- [ ] 프로젝트 필터 결과가 정상적으로 바뀜
- [ ] 공개 범위 안내가 읽기 쉽게 표시됨

### 키보드
- [ ] Tab으로 ‘본문으로 바로가기’에 접근 가능
- [ ] Tab으로 테마 버튼과 프로젝트 필터에 접근 가능
- [ ] Enter/Space로 버튼 조작 가능
- [ ] 포커스 위치가 화면에서 분명히 보임

## 프로젝트 자료 검사

- [ ] Repository 링크가 있는 경우 전부 직접 공개 가능한 저장소인지 확인
- [ ] 스크린샷에 개인정보·계정명·경로·API Key 등 민감정보가 없음
- [ ] 타사 로고·캐릭터·게임 화면 등은 필요한 범위만 사용하거나 가림
- [ ] 원본 게임 파일·에셋 다운로드 링크를 포함하지 않음

- T01-C05: 결과물의 `#scope` 영역과 `docs/T01-SCOPE.md`에 비공개 정보 3개 이상 명시
