# T01 제출 준비

> 실제 제출 직전에 URL과 테스트 결과를 다시 확인하고 이 문서를 최종 갱신합니다.

## 결과물

- 결과물 주소: 배포 후 입력
- 소스 주소: https://github.com/Huihuing/Report

## 짧은 확인 방법 4줄

1. **위치:** 공개 결과물 주소의 첫 화면에서 시작합니다.
2. **3단계 이내 행동:** 프로젝트 영역으로 이동 → ‘개발’ 필터 선택 → GitHub 링크를 엽니다.
3. **통과 모습:** 선택한 범주의 카드만 남고 공개 GitHub 페이지가 새 탭에서 정상적으로 열립니다.
4. **안 될 때 모습:** 필터를 눌러도 카드가 바뀌지 않거나 링크가 로그인·권한 요청 또는 오류 화면으로 이동합니다.

## AI와 나의 판단 3줄

1. **AI에게 맡긴 일:** 페이지의 기본 구조, 반응형 CSS, 키보드 접근이 가능한 버튼 동작과 제출용 점검 문서 초안을 작성하게 했습니다.
2. **직접 판단한 일:** 누구에게 무엇을 보여줄지, 어떤 개인 정보를 공개하지 않을지, 어떤 프로젝트 경험을 대표 사례로 사용할지 결정했습니다.
3. **AI 제안을 따르지 않은 일:** 이력서처럼 개인정보와 경력을 많이 나열하는 방식보다 과제 목적에 맞게 관심 분야와 작업 방식을 중심으로 공개하기로 판단했습니다.

## 화면·상호작용 검사

### 기준 화면 A — 모바일
- 권장 확인 크기: 390 × 844
- [ ] 가로 스크롤 없음
- [ ] 제목과 버튼이 겹치지 않음
- [ ] 프로젝트 카드가 한 열로 표시됨
- [ ] 모든 링크와 버튼을 누를 수 있음

### 기준 화면 B — 데스크톱
- 권장 확인 크기: 1440 × 900
- [ ] 본문 폭과 여백이 자연스러움
- [ ] 카드가 겹치거나 잘리지 않음
- [ ] 프로젝트 필터 결과가 정상적으로 바뀜
- [ ] 외부 링크가 정상적으로 열림

### 키보드
- [ ] Tab으로 ‘본문으로 바로가기’에 접근 가능
- [ ] Tab으로 테마 버튼과 프로젝트 필터에 접근 가능
- [ ] Enter/Space로 버튼 조작 가능
- [ ] 포커스 위치가 화면에서 분명히 보임
