# T01 공개 범위 점검표

## 대상과 목적

**대상:** 함께 공부하거나 일할 사람, 프로젝트를 처음 보는 사람  
**목적:** 임희재가 무엇에 관심이 있고 어떤 방식으로 개발 문제를 해결하는지 한 페이지에서 보여준다.

## 공개할 정보

1. 소프트웨어 개발을 공부하고 있다는 점
2. 웹·백엔드, 레거시 소프트웨어, 아카이브/복원에 관심이 있다는 점
3. 공개 가능한 프로젝트의 설명과 저작권·라이선스 검토를 마친 스크린샷
4. 전부 직접 작성했거나 공개 권한이 명확한 경우에만 개별 Repository 주소
5. 문제를 확인하고 작게 검증하며 과정을 기록하는 작업 방식

## 공개하지 않을 정보

1. 전화번호, 개인 이메일, 상세 주소와 같은 직접 연락·식별 정보
2. 비밀번호, API Key, 토큰, 쿠키, 환경변수 등 비밀값
3. 주민번호·금융정보·개인 문서처럼 과제와 관계없는 개인정보
4. 제3자 게임 클라이언트·에셋·원본 파일·복제물이 포함된 저장소 주소 또는 파일
5. 공개 허가 여부가 불분명한 코드, 이미지, 음원, 캐릭터, 로고 등의 원본 자료
6. 비공개 저장소의 코드와 내부 파일 구조

## 프로젝트 공개 원칙

- 기본값은 **설명 + 스크린샷**입니다.
- Repository 링크는 전부 직접 작성했거나 공개 권한이 명확한 프로젝트에만 추가합니다.
- 스크린샷도 제3자 저작물이 과도하게 노출되지 않도록 가능한 한 내가 만든 UI, 도구, 코드 실행 결과 중심으로 사용합니다.
- 필요한 경우 게임 화면·캐릭터·로고·파일명·계정정보를 크롭하거나 가립니다.
- 출처 표시가 필요한 자료는 출처를 함께 기록합니다.

## 공개 전 확인

- [ ] 결과물 주소가 새 시크릿 창에서 로그인 없이 열린다.
- [ ] 소스 주소가 새 시크릿 창에서 로그인 없이 열린다.
- [ ] 결과물에 공개하지 않기로 한 정보가 없다.
- [ ] 저장소에 비밀값이나 환경설정 파일이 없다.
- [ ] 각 프로젝트 스크린샷의 공개 가능 범위를 다시 확인했다.
- [ ] Repository 링크가 있는 프로젝트는 공개 권한이 명확하다.
