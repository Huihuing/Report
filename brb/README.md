작성자: **limheejae**

## 논문의 결론을 사용하는 앱 한 문장

Python에서 정수의 존재 여부를 확인하는 개발자가 데이터 크기와 조회 위치를 선택하면, T10 논문의 list/set 측정 결과와 조건부 자료구조 선택 가이드를 보여 주는 앱입니다.

**논문:** 「정수 원소의 존재 여부 검사에서 컨테이너 종류·크기·조회 위치가 실행 시간에 미치는 영향」

- 출처: ../t10/paper.md
- 실험 데이터 원본: ../t10/data/analysis.json
- 540개의 측정 블록, 9조건, 조건당 30블록 / 조회 1회당 중앙값
- 대상은 정수 0부터 n-1, 크기는 100 / 1,000 / 10,000이며 조회 조건은 -1 / 0 / n-1입니다.
- 한 번의 CPython 3.13.5 Linux 실험 결과이므로 다른 환경에서 절대 실행시간이나 성능 배수를 보장하지 않습니다.

## 사용자가 직접 할 일 세 가지

1. 데이터 크기(100, 1,000, 10,000)와 조회 위치(부재/첫/마지막)를 선택합니다.
2. **측정값 비교하기**를 눌러 논문의 실제 list/set 중앙값과 조건부 추천을 확인합니다. 순서 보존 체크를 켜면 추천이 바뀝니다.
3. 임의 정수(-1, 0, n-1 등)를 입력해 존재 여부 판정을 시험합니다. 중간 원소의 *존재 여부*는 알려 주지만 그 위치의 Python 실행시간을 만들어 내지는 않습니다.

## 실행 및 제출

### 공개 URL

https://report-huihuing.vercel.app/brb/ (main 배포가 완료된 뒤 확인)

로그인, 회원가입, API 키, 타인 데이터가 필요하지 않습니다. Vercel의 기존 **report** 프로젝트에서 /brb/로 배포합니다. 새 프로젝트를 만들지 않습니다.

### 로컬 실행 묶음

브라우저만 있으면 됩니다. 이 폴더 전체를 ZIP으로 압축하거나 새 임시 폴더에 복사한 뒤 **brb/index.html을 더블 클릭**합니다. 외부 API와 빌드 명령이 필요하지 않습니다. 상대 경로를 유지할 파일: brb/index.html, brb/styles.css, brb/app.js, brb/data/research.js. 사이트 내 T10/포트폴리오 링크는 로컬 브라우저의 상위 폴더에 해당 페이지가 있을 때만 열리며, 앱 자체는 단독으로 동작합니다.

### 연구 데이터 동기화 점검

저장소 루트에서 Python 3.10+로 다음 명령 실행:

    python brb/tests/verify.py

출력에 BRB_VERIFY_OK가 나오면 9개 사례의 핵심 측정값이 T10 원자료와 일치하고, 앱/포트폴리오 필수 링크가 존재한다는 뜻입니다. 브라우저의 키보드 조작과 신규 시크릿 창 확인은 별도로 수행해야 합니다.

## 잘못된 입력과 데이터

- 빈 문자열, 소수, 기호, 12자리 초과 정수는 안내 문구로 처리하며 앱이 멈추지 않습니다.
- 실측 범위 밖 수치에 대한 성능 예측은 하지 않습니다. 중간 값 입력은 *존재 여부만* 예시로 판단합니다.
- 새 실험을 실행하지 않습니다. 모든 시간 수치는 T10 analysis.json의 보관된 결과입니다.
- 막대는 같은 조건의 조회시간에 비례하지만, 짧은 막대는 가독성을 위해 최소 2%로 표시합니다.
- 예시 데이터는 0…n-1의 정수이며 사람의 실제 데이터/연락처/비밀값을 사용하지 않습니다.
- 개인정보, 인증, 쿠키, 로컬 저장소, AI API, 외부 CDN, 서버측 호출을 사용하지 않습니다.
